# 阶段三：语义奖励生成（Semantic Reward Generation）

## 概述

语义奖励生成阶段将 Stage 2 产出的抽象自然语言子目标**转化为机器可执行的奖励规则**。这是连接"语义意图"与"强化学习训练"的关键桥梁，使 RL 智能体能够以可量化的方式理解并验证每个游戏步骤是否完成。

---

## 核心目标

> 对子目标序列 $S$ 中的每个子目标 $sg_j$，使用 LLM 生成一个对应的**形式化、可执行的奖励规则**，该规则只使用游戏环境的可观测状态变量来定义成功条件。

---

## 输入

| 输入项 | 来源 | 内容 |
|--------|------|------|
| 子目标序列 $S = (sg_1, \dots, sg_n)$ | Stage 2 输出 | 自然语言步骤列表 |
| 环境观测模式（Observation Schema） | 游戏环境 | 所有可观测状态变量的清单（位置、持有物品、物品状态等）|

---

## 技术流程

### 步骤 1：逐子目标生成奖励规则

对序列 $S$ 中的每个 $sg_j$，LLM 被提示（prompted）生成一个具体的奖励规则，该规则：

- **仅使用** observation schema 中声明的变量
- **精确定义**该子目标的成功条件
- **以 JSON 格式输出**，便于代码直接解析执行

### 步骤 2：输出奖励函数序列

生成一个与子目标序列**一一对应**的奖励函数序列：

$$R = (r_1, r_2, \dots, r_n)$$

其中每个函数：

$$r_j : \text{State} \to \mathbb{R}$$

是一个**二值谓词**（binary predicate）：
- 若当前游戏状态满足 $sg_j$ 的成功条件 → 返回正奖励
- 否则 → 返回 0

---

## 动机示例（"Bake the Pizza" 子目标）

**子目标 $sg_4$**：`"Bake the assembled pizza in the oven"`

**LLM 生成的奖励规则（JSON 格式）：**

```json
{
  "subgoal": "Bake the assembled pizza in the oven",
  "reward_rules": [
    {
      "event": "place_raw_pizza_in_oven",
      "condition": "raw_pizza in oven_contents",
      "reward": 10,
      "description": "奖励：将生披萨放入烤箱"
    },
    {
      "event": "baking_progress",
      "condition": "oven_bake_progress increased",
      "reward": 5,
      "description": "奖励：每次可观测的烘烤进度提升"
    },
    {
      "event": "pizza_baked",
      "condition": "pizza_state transitions from 'raw' to 'finished'",
      "reward": 50,
      "description": "奖励：披萨从生变熟（终态达成）"
    }
  ]
}
```

可以看到，对于"烘烤披萨"这一子目标，LLM 将其细化为**三个阶段性奖励**：
1. 放入动作奖励
2. 过程进度奖励
3. 最终状态转变奖励

---

## 奖励序列的作用

```
R = (r1,  r2,  r3,  r4)
     ↓     ↓     ↓     ↓
    取番茄 处理酱 组装  烘烤
    奖励   奖励  奖励  奖励
```

序列 $R$ 为 Stage 5 的自适应混合奖励函数提供**有序检查点（checkpoints）**，RL 智能体必须按正确顺序依次满足这些检查点，形成课程式学习（curriculum learning）结构。

---

## 与纯任务完成奖励的对比

| 对比维度 | 传统 PPO（仅任务完成奖励） | SMART 语义奖励 |
|----------|--------------------------|----------------|
| 奖励粒度 | 粗粒度（只有最终成功/失败）| 细粒度（每个子目标都有反馈）|
| 稀疏性问题 | 严重（智能体长期无奖励信号）| 缓解（有序子目标提供密集引导）|
| 对"捷径"的依赖 | 高（倾向于找最短路径）| 低（每步都有明确目标）|
| 能否验证功能意图 | 部分（只验证最终结果）| 是（验证每个中间步骤）|

---

## 关键设计约束

1. **只使用可观测变量**：奖励规则不依赖任何内部隐藏状态，确保奖励函数可在运行时真正执行
2. **格式化输出（JSON）**：LLM 输出直接可解析，无需额外的代码编写
3. **有序性**：$R$ 中的函数顺序与 $S$ 中子目标顺序严格对应，Stage 5 按顺序激活

---

## 关键价值

1. **自动化**：无需测试工程师手写奖励函数，LLM 全自动生成
2. **语义对齐**：奖励规则与游戏意图精确对应，而非只依赖代码覆盖率
3. **课程学习基础**：有序的奖励序列为 RL 训练提供了天然的难度递进结构，大幅降低稀疏奖励问题
4. **可组合性**：与 Stage 5 的结构性奖励结合，形成混合奖励机制
