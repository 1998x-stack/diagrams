# 阶段五：自适应混合奖励函数（Adaptive Hybrid Reward Function）

## 概述

自适应混合奖励函数是 SMART 框架的**执行核心**，负责将前四个阶段的所有输出整合为一个统一的训练信号，驱动 RL 智能体在**完成功能目标**的同时**主动探索结构变更**。这是实现"功能正确性"与"结构完备性"双重目标的关键机制。

---

## 核心目标

> 训练一个 RL 智能体，使其能够在单次 episode 内**按顺序完成所有子目标**，同时在多个 episode 的训练过程中**持续发现并覆盖所有修改过的代码路径**。

---

## 双层状态追踪设计

| 状态类型 | 变量 | 重置时机 | 作用 |
|----------|------|----------|------|
| **Episode 内进度追踪** | 子目标索引 $j$ | 每个 episode 开始时重置 | 追踪当前应完成第几个子目标 |
| **全局覆盖地图** | $C_{cov}$ | **全程不重置**，跨 episode 持久化 | 记录哪些结构锚点已被触发过 |

---

## 混合奖励计算

每个时间步 $t$，总奖励 $r_t$ 由两部分组成：

$$r_t = r_t^{sem} + r_t^{str}$$

### 语义奖励 $r_t^{sem}$（Semantic Reward）

**触发条件**：当前状态满足第 $j$ 个子目标的成功条件

```python
if j <= n and r_j(s_{t+1}) > 0:
    r_t += r_sem       # 给予语义奖励
    j += 1             # 子目标索引前进到下一个
```

- 奖励值为固定的 $r^{sem}$
- 完成最终任务额外获得终端奖励（论文设置为 200）
- 子目标奖励范围：10 ~ 50（根据子目标复杂度）

### 结构性奖励 $r_t^{str}$（Structural Reward）

**触发条件**：当前步骤触发了**尚未被覆盖**的结构锚点

```python
for c in C_step:           # 本步触发的所有锚点
    if c not in C_cov:     # 若该锚点从未被触发
        r_t += r_str       # 给予结构性奖励（一次性）
        C_cov.add(c)       # 标记为已覆盖（全局持久化）
```

- 每个锚点**只奖励一次**（发现奖励，非重复奖励）
- 奖励值为固定的 $r^{str}$

---

## 算法伪代码（Algorithm 1）

```
输入：
  S = (sg1, ..., sgn)    子目标序列
  R = (r1, ..., rn)      奖励函数序列
  C                      全体结构锚点集合
  r_sem, r_str           奖励幅度

初始化：C_cov ← ∅

for each episode e = 1, ..., E do:
  重置环境
  j ← 1                  # 重置子目标索引

  for each step t = 0, ..., T-1 do:
    at ← π(st)           # 智能体选择动作
    (s_{t+1}, done, C_step) ← env.step(at)

    r_t ← 0

    # 语义奖励
    if j <= n and r_j(s_{t+1}) > 0:
        r_t += r_sem
        j += 1

    # 结构性奖励
    for c in C_step:
        if c not in C_cov:
            r_t += r_str
            C_cov.add(c)

    存储 (st, at, r_t, s_{t+1}, done) 到 D_e
    if done: break

  使用 D_e 中的轨迹更新策略 π（PPO）
```

## 动态过程解析（以披萨任务为例）

### 早期 Episode：以语义奖励为主驱动

```
智能体学习：拿起番茄 → 使用砧板（满足 sg1）
                ↓
  获得 r_sem（大额奖励）+ r_str × 3（新覆盖 c1, c5, c8）
                ↓
  继续学习 sg2 → sg3 → sg4...
```

智能体首先学习**"幸福路径"（happy path）**，即完成任务的最优序列。

### 中后期 Episode：语义奖励稳定，结构奖励推动探索

```
语义奖励路径已学会 → 结构奖励沿 happy path 耗尽（已全覆盖）
                ↓
  为追求更高总奖励，智能体开始"偏离常规"：
  - 在不同砧板上切番茄
  - 在切前尝试与其他厨房工具交互
  - 尝试边角案例（发现 c12：切菜逻辑的边缘情况）
```

这种**探索-利用权衡**由奖励机制自然涌现，无需人工设计探索策略。

---

## 为何不产生训练不稳定？

论文参考好奇心驱动 RL（Curiosity-driven RL）的研究，通过三重机制保证稳定性：

| 机制 | 说明 |
|------|------|
| **语义奖励作为"骨干"** | 每个 episode 都稳定可得，为策略提供固定的学习基础 |
| **结构奖励作为"递减奖金"** | 随着覆盖率提升自然减少，不会持续压倒语义目标 |
| **PPO 的熵正则化** | 内置的策略随机性惩罚防止过早收敛，天然补充探索驱动 |

## 代码检测实现细节

结构性奖励的实现依赖**自动代码插桩（automated code instrumentation）**：

```
训练开始前：
  使用 pytest 等标准动态分析工具对游戏源代码进行插桩
  在关键行和控制流分支处插入轻量级探针（probes）
  探针不改变核心游戏逻辑

运行时：
  智能体执行动作 → 游戏引擎运行对应代码 → 探针触发
  将本步触发的锚点集合通过 info['covered_anchors'] 返回给 RL 环境
  环境据此计算结构性奖励
```

**特点**：
- 全自动，无需手动修改代码
- 计算开销极小
- 与游戏逻辑解耦

## 实验结果对比

| 方法 | 行覆盖率 | 分支覆盖率 | 任务成功率 | 平均步长 |
|------|----------|------------|------------|----------|
| Random | 0.31 | 0.35 | 0.06 | 286 |
| PPO | 0.55 | 0.58 | 0.65 | 45 |
| PPO+ICM | 0.53 | 0.55 | 0.62 | 43 |
| **SMART-Full** | **0.93** | **0.98** | **0.98** | 55 |
| SMART-Semantic Only | 0.52 | 0.61 | 0.96 | 40 |
| SMART-Structural Only | 0.31 | 0.28 | 0.05 | 287 |

**关键发现**：
- SMART-Full 分支覆盖率达 98%，约为传统 RL 的 **2 倍**
- 任务成功率 98%，证明结构探索**不以功能正确为代价**
- 步长略长（55 vs 40），这是**"生产性低效"**：多出的步骤用于触发边缘案例代码

---

## "生产性低效"的测试语义

> 在传统 RL 任务中，步长增加 = 性能下降。
>
> 在**测试场景**中，步长增加 = **智能体主动探索了更多代码路径**，是正向指标。

SMART 的设计有意接受这种"低效"，因为它代表着测试价值，而非任务能力的退步。

---

## 关键价值

1. **双目标统一**：单一奖励函数同时优化功能验证和结构覆盖，无需两个独立系统
2. **自然涌现探索**：结构奖励的递减特性自然激励智能体偏离已知路径，无需显式探索策略
3. **全自动化**：从代码插桩到奖励计算，全程无需人工干预
4. **可扩展性**：在 Minecraft 等更复杂环境中同样有效（行覆盖 92%，分支覆盖 94%）

---

## 局限性与未来方向

**挑战 1：奖励权重调参**
> 结构性奖励与语义奖励的相对权重难以确定，过度偏向结构奖励可能导致智能体"刷浅层代码路径"而忽略深层功能验证。

**挑战 2：防御性代码的覆盖盲区**
> 极端边缘情况（如"非法食材叠放顺序"的保护性检查）需要反直觉的行为才能触发，当前设计仍存在约 5~8% 的覆盖缺口。

**未来方向**：
- 与模糊测试（fuzz testing）结合，暴力触发防御性分支
- 与符号执行（symbolic execution）结合，通过约束求解覆盖死代码
- 引入动态奖励调整机制，自适应平衡两类奖励
