# 论文深度解析

## LLMs May Not Be Human-Level Players, But They Can Be Testers: Measuring Game Difficulty with LLM Agents

> **作者**: Chang Xiao (Adobe Research) · Brenda Z. Yang (Columbia University)
> **发表时间**: 2024年10月1日
> **arXiv**: 2410.02829v1 [cs.AI]

---

## 1. 核心问题与动机

### 1.1 问题背景

游戏难度平衡是游戏开发的核心挑战之一。难度曲线（Difficulty Curve）若设计不当：
- **过难** → 玩家挫败感，放弃游戏（Elden Ring 案例：上线后因过难引发大量差评，被迫降低难度）
- **过易** → 失去挑战性，玩家脱离

**传统评估方式**：招募人工测试员逐关评测 → 耗时、昂贵、难以迭代

### 1.2 核心研究问题

> **Can LLMs be used to measure game difficulty?**
> LLM 能否作为有效的游戏难度评估工具？

### 1.3 研究假设

LLM 虽不一定达到人类玩家的游戏水平，但其在特定关卡上的**相对表现趋势**应与人类玩家的难度感知高度相关。

## 3. 框架架构（Framework Architecture）

```
┌─────────────────────────────────────────────────────┐
│                    LLM Agent                        │
│  ┌─────────────────┐    ┌──────────────────────┐   │
│  │  Game I/O        │    │  Instruction         │   │
│  │  Component       │    │  Component           │   │
│  │                  │    │                      │   │
│  │ ① 解析游戏状态   │    │ ① Game Rule          │   │
│  │ ② 整理关键信息  │◄──►│ ② Game Strategy      │   │
│  │ ③ 转换为动作    │    │ ③ Prompting Tech     │   │
│  └─────────────────┘    └──────────────────────┘   │
└─────────────────────────────────────────────────────┘
         ▲                              ▼
    游戏状态信息                    LLM 输出动作
         │                              │
┌────────┴──────────────────────────────▼──────┐
│              Game Environment                 │
│         (Wordle / Slay the Spire)             │
└───────────────────────────────────────────────┘
```

### 3.1 Game I/O Component

- **输入**：从游戏 API 获取实时游戏状态（玩家状态、可用动作、对手状态、历史）
- **处理**：将状态信息转为自然语言文本
- **输出**：将 LLM 的文本响应转换为可执行的游戏动作

### 3.2 Instruction Component（三层结构）

```
┌─────────────────────────────────────┐
│           Game Rule                 │  ← 所有 Agent 共用
│  解释游戏规则，确保 LLM 理解玩法     │
├─────────────────────────────────────┤
│           Game Strategy             │  ← 特定 Agent 使用
│  注入外部策略知识，模拟人类玩法风格   │
├─────────────────────────────────────┤
│        Prompting Techniques         │  ← 引导推理方式
│  Zero-Shot / CoT / CoT+             │
└─────────────────────────────────────┘
```

### 3.3 三种 Prompting 策略

| 策略 | 描述 | 特点 |
|------|------|------|
| **Zero-Shot (ZS)** | 仅提供规则，直接猜测 | 基准，无推理引导 |
| **CoT** | Chain-of-Thought，逐步推理后决策 | 提升推理质量 |
| **CoT+** | CoT + 外部专家策略 | 最强，融合领域知识 |

## 4. 游戏选择标准

论文选择游戏的三个原则：

1. **游戏信息可文本表达** → 排除第一人称射击等视觉密集型游戏
2. **真实、广泛游玩的原版游戏** → 保证外部效度，避免简化版
3. **有公开人类游戏数据** → 可与人类难度指标做 Pearson 相关性分析

## 5. 实验一：Wordle

### 5.1 游戏简介

- 纽约时报旗下文字猜词游戏，约 30 万日活
- 玩家有 6 次机会猜一个 5 字母单词
- 反馈：🟩绿（位置正确）/ 🟨黄（字母存在但位置错）/ ⬜灰（字母不存在）

### 5.2 实验设计

- **数据集**：529 个谜题（2024.3.7 ~ 2024.8.16，来自 WordleBot）
- **难度指标**：人类平均猜测次数（越多 = 越难）
- **每题试验**：每个 Agent 对每道题进行 20 次试验，取平均猜测次数
- **基准扩展**：将原始 6 次猜测上限扩展至 12 次（确保 LLM 有足够表现差异）

### 5.3 Agent 配置

```
6 种配置：
├── Wordle Solver（信息论最优，基准）
├── GPT-3.5 Turbo ZS
├── GPT-3.5 Turbo CoT
├── GPT-3.5 Turbo CoT+
├── GPT-4 ZS
├── GPT-4 CoT
└── GPT-4 CoT+
```

### 5.4 结果（Table 1）

| Agent | 平均猜次 | 相关系数 r | p 值 |
|-------|---------|-----------|------|
| **Wordle Solver** | 3.55 | 0.075 | 0.124（不显著）|
| GPT-3.5 ZS | 9.35 | 0.237 | <0.001 |
| GPT-3.5 CoT | 7.65 | 0.365 | <0.001 |
| GPT-3.5 CoT+ | 7.41 | 0.387 | <0.001 |
| GPT-4 ZS | 7.79 | 0.259 | <0.001 |
| GPT-4 CoT | 6.802 | 0.435 | <0.001 |
| **GPT-4 CoT+** | **5.12** | **0.624** | **<0.001** |
| Human Average | 3.97 | — | — |

### 5.5 关键发现

- **LLM 游戏水平低于人类**（5.12~9.35 猜次 vs 人类 3.97）
- **LLM 与人类难度感知强相关**（GPT-4 CoT+ r=0.624, p<0.001）
- **Wordle Solver 相关性极弱**（r=0.075）→ 信息论最优解 ≠ 人类玩法模拟
- **更强的 LLM + 更好的 Prompt → 更高相关性**

## 6. 实验二：Slay the Spire（StS）

### 6.1 游戏简介

- 构筑卡牌 + 肉鸽（Roguelike）单人游戏
- 逐关打怪，每胜一场选新卡牌强化牌组
- 100+ 种卡牌组合，策略深度极高
- 公开数据集：7500 万+ 场游戏记录

### 6.2 技术实现

- **BasicMod**：提供命令行接口修改游戏状态
- **CommunicationMod**：通过 stdin/stdout 暴露 Python API，实现 LLM 与游戏的程序化交互

### 6.3 实验设计

- **测试范围**：Act 1 + Act 2 的所有 Boss
- **固定角色**：Ironclad（使用均衡强度牌组）
- **LLM 牌组补偿**：提供比普通玩家更强的牌组（补偿 LLM 游戏能力不足）
- **难度指标**：LLM 战斗结束时的**剩余 HP**（越高 = 越轻松 = 敌人越弱）
- **人类基准**：各 Boss 的人类平均胜率

### 6.4 结果（Table 2）

| Act | Agent | Avg HP | r | p |
|-----|-------|--------|---|---|
| Act 1 | Random | 12.717 | 0.231 | 0.075 |
| Act 1 | GPT-3.5 ZS | 8.650 | 0.471 | <0.001 |
| Act 1 | GPT-3.5 CoT | 19.917 | 0.513 | <0.001 |
| Act 1 | GPT-4 ZS | 22.550 | 0.657 | <0.001 |
| Act 1 | **GPT-4 CoT** | **36.733** | **0.871** | **<0.001** |
| Act 1 | Rule-based Expert AI | 32.400 | 0.742 | <0.001 |
| Act 2 | **GPT-4 CoT** | 17.583 | **0.710** | <0.001 |

### 6.5 关键发现

- **GPT-4 CoT 与人类相关性 r=0.871（Act 1）**，极强相关
- **LLM 优于规则专家 AI（r=0.742）**：LLM 独立发展类人策略，而非被硬编码
- 越接近人类推理过程的 Agent → 对人类游玩难度模拟越准确

## 7. 定性分析：GPT-4 CoT 的决策样例

```
当前状态：Energy=3, HP=64, Strength=12
敌人：Spike Slime (52HP, Debuff) + Acid Slime (52HP, 16伤害攻击)

LLM 分析流程：
① 优先威胁识别：Acid Slime 即将造成 16 点伤害 → 主威胁
② 逐牌评估（以Spot Weakness举例）：
   - 优点：如果敌人攻击意图则 +3 Strength
   - 缺点：条件触发，只有敌人攻击时有效
   - 总评：Acid Slime 有攻击意图 → 本回合有效
③ 最优策略：先打 Spot Weakness → 提高 Strength 至 15
   然后 Heavy Blade（14 + 3*15 = 59 伤害）→ 一击必杀
```

## 8. 五条实践指南（G1-G5）

### G1：文本表示格式至关重要
- 游戏信息必须以 LLM 易于处理的自然语言呈现
- 案例：Wordle 中将单词表示为字母列表 `[A, P, P, L, E]` 而非纯文本 "APPLE"
  - 原因：LLM 会将"APPLE"拆分为子词 token（如"APP"+"LE"），影响位置理解

### G2：为 LLM 性能不足设置补偿机制
- LLM 普遍低于人类玩家水平，需适度补偿（如增加猜测次数上限、提供更强牌组）
- 补偿原则：不能过度，否则 LLM 每关都轻松完成，失去难度区分度

### G3：聚焦相对难度而非绝对难度
- LLM 不适合预测单个关卡的绝对通过率
- 适合评估**一批关卡之间的相对难度排序**

### G4：使用更强大的 LLM + 更好的 Prompting
- GPT-4 > GPT-3.5，CoT > ZS，CoT+ > CoT
- 策略知识应反映典型玩法，不要是"破解技巧"（否则会产生偏差）

### G5：少量人类数据辅助校准
- 用小规模人类数据做 Pilot Study，可帮助确定最佳难度指标（胜率 vs 得分 vs 时间）

## 9. 局限性与未来工作

| 局限 | 说明 |
|------|------|
| **无法处理累积效应** | 当前框架处理独立关卡，无法建模技能成长、资源累积等跨关效应 |
| **固定能力模型** | LLM 每次响应仅依据当前信息，不能模拟人类的学习与适应 |
| **文本限制** | 视觉密集型游戏无法直接适用，需等待多模态模型发展 |
| **测试范围窄** | 仅测试游戏难度，未涉及 Bug 检测、平衡性分析等其他测试维度 |

---

## 10. 结论

> LLM 不是最强玩家，但可能是最通用的游戏测试员。

- LLM 以**最小调整、通用提示**即可在多款游戏上实现与人类难度感知的强相关
- 相比深度强化学习（需大量算力 + 游戏特化），LLM 具有**低成本、高迁移性**优势
- 本研究为 LLM 在游戏开发流程中的落地提供了首个系统性验证框架
