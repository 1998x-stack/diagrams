# UrhoX 游戏开发稳定优化模式

本技能提炼自大量处于"稳定成功平台期"（stable success plateau）的真实开发 session。核心命题：**事情顺利时，维持策略；不要为了"更好"引入变化。**

---

## 识别稳定平台期

以下信号表明当前处于稳定成功状态：

- 连续多次操作无报错、无用户纠正
- 任务在既定路径上顺利推进（如批量文本替换、参数批量调整）
- 用户未提出新的方向性要求

**正确行为：** 维持当前策略，按既定节奏继续执行。  
**错误行为：** 主动切换工具、引入"优化"、重构未出问题的部分。

---

## 稳定期执行规范

### 定位阶段（精准，不过度搜索）

使用 `Glob` 或 `mcp__mkr__Read` 锁定目标文件范围：
- 先用 Glob 确认文件存在，再 Read 读取内容
- 不要"顺手"读取不相关文件
- 搜索到即执行，不等待更多上下文

### 修改阶段（保守，单次变更范围最小）

- 每次只改一处，确认效果后再改下一处
- 坐标、像素值、颜色等参数修改后立即验证
- 不要在一次 Edit 中混入多个独立改动

### 多端适配

当需要覆盖多种分辨率或设备时：
- 优先按主流分辨率验证，再扩展至边缘情况
- UI 响应式逻辑修改后，在不同端配置下各验证一次
- 不要假设"一端正确则全部正确"

### 即时回滚

用户发出任何纠正（包括"回退上一步"、"不要这个效果"）：
- 立即执行回滚，不解释、不辩解
- 回滚后重新确认用户意图，再开始下一轮修改

---

## 文档驱动迭代

当任务由设计文档驱动时（用户给出规范文档、策划案、需求说明）：

1. 先完整阅读文档，提取本轮要执行的具体变更点
2. 按文档顺序逐条执行，不跳跃、不合并步骤
3. 执行完成后，检查文档是否需要反向同步（代码实际情况与文档描述不符时更新文档）
4. 保持"代码即文档最终态"的原则

## 与 uruhox-workflow 的关系

| 场景 | 使用哪个技能 |
|---|---|
| 开始一个新任务、功能未知 | `uruhox-workflow` |
| 任务已在顺利推进、精细调优 | `uruhox-optimize`（本技能）|
| 高频视觉反馈迭代 | `uruhox-workflow`（高频视觉调优模式）|
| 文档驱动的批量修改 | `uruhox-optimize`（文档驱动迭代）|
