# UrhoX 游戏开发核心工作流

本技能提炼自大量真实游戏开发 session 的轨迹分析，覆盖 UI 迭代、功能开发、文档同步、视觉调优等高频场景。

---

## 标准开发循环

适用于：功能新增、UI 布局调整、资源修复、文档同步。

**执行顺序：**

1. **Read 先行**  
   使用 `mcp__mkr__Read` 读取目标脚本、配置文件和设计文档，建立上下文。  
   不要假设当前状态——先读，再动手。

2. **规划后执行**  
   用 `TodoWrite` 拆解任务步骤，顺序写下"要做什么"，而非具体文件名。  
   - 任务有 3 步及以上时必须先写 Todo  
   - 每条 Todo = 一个可独立验证的动作

3. **精准修改**  
   调用 `mcp__mkr__Edit` 或 `mcp__mkr__Write` 执行代码变更：  
   - UI 坐标、间距、颜色调整  
   - 文本替换与本地化  
   - 资源路径修复

4. **验证效果**  
   执行 `mcp__sce-urhox__build` 后确认：  
   - 无遮挡、无报错  
   - 交互逻辑（按钮事件、撤销/重置）功能正常

5. **同步文档**  
   代码修改完成后，立即更新对应设计文档，保持代码与文档的一致性。  
   文档滞后视为未完成。

6. **监听纠正信号**  
   用户发出撤销或纠正指令时，立即回滚，不辩解，重新调整策略。

---

## 高频视觉调优模式

适用于：像素级调整、视觉参数反复迭代、用户实时给反馈的场景。

**与标准循环的区别：**
- Todo 可省略，直接进入 Edit → Build → 等待反馈 的快速循环
- 每次修改范围尽量小，便于快速定位哪步引入了问题
- `mcp__mkr__Edit` + `mcp__sce-urhox__build` 形成紧凑的"改→看→调"节奏

**注意：** 高频迭代中更容易产生遗漏。每隔 3-5 轮确认一次文档是否需要同步。

---

## 工具数据刷新

当任务需要获取最新开发者列表、平台数据或其他实时信息时：

- **不要复用历史调用结果**——强制发起新的工具调用
- 验证返回数据是当前状态，而非缓存快照
- 若用户指出数据陈旧，立即重新调用，不使用本地记忆中的旧值
