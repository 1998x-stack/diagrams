# 编程工作流行为规律

本技能提炼自大规模真实编程会话的轨迹分析，涵盖多个项目、数百次迭代。以下四条规律在不同语言、工具链、项目类型中反复出现，具有通用性。

---

## 规律一：先搜索，再动手

在任何 Edit 或 Write 操作之前，先用 Grep 或 Glob 定位目标。

- 不要凭假设猜测文件位置或内容
- 用 Grep 确认符号/字符串的实际位置
- 用 Glob 确认文件范围
- 搜索确认后，再执行修改

**典型错误**：直接 Edit 某个路径，结果文件结构已变，或目标在另一处。

---

## 规律二：TodoWrite 是分解工具，不是记录工具

多步骤任务开始前先写 TodoWrite，而不是完成后补记。

- 任务涉及 3 步及以上：先列 Todo，再开始执行
- 每条 Todo 对应一个可独立验证的动作
- 执行过程中逐条勾选，不要在结尾批量标记完成

**原理**：提前外化计划能防止中途漂移，避免遗漏步骤或陷入局部细节。

---

## 规律三：识别并保持稳定成功态

当连续多次操作均无报错、无用户纠正时，处于"稳定成功平台期"。正确行为是：**维持当前策略，不引入变化**。

- 不要在"顺利"时主动切换工具或思路
- 不要为了"更好"而引入未被要求的改动
- 只在以下情况打破稳定态：收到用户纠正、出现新类型错误、任务阶段发生切换

**典型错误**：事情顺利时过度"优化"，引入新问题。

---

## 规律四：代码与文档同步演进

代码变更完成后，立即更新相关文档，不留待后续处理。

- 每次修改行为、接口、结构后：检查是否有文档引用了被改动的内容
- 将文档更新视为本次任务的一部分，而非独立后续任务
- 文档滞后 = 隐性债务，积累后难以追溯

**适用范围**：README、注释、API 文档、设计文档、变更日志均适用。
