# 游戏设计评审清单

> 快速检查用。在任何设计提案进入开发前，用这份清单做最后检查。

---

## 🔵 新功能/系统评审清单

### 体验层
- [ ] 能描述玩家在具体游戏瞬间感受到什么吗？
- [ ] 去掉所有外部奖励，这个系统本身还有趣吗？
- [ ] 与现有核心体验柱是否一致？有无冲突？

### 引导层
- [ ] 玩家无需读教程能理解基础吗？
- [ ] 第一次接触时是否有零惩罚的探索空间？
- [ ] 失败反馈是否明确指向改进方向？

### 系统层
- [ ] 核心规则是否简单（能1-2句说清楚）？
- [ ] 是否与其他系统产生有趣的交互（而非孤立）？
- [ ] 边界条件是否都考虑到了？
- [ ] 数值范围是否经过基础验证？

### 体验影响层
- [ ] 是否影响游戏节奏（打断心流 or 丰富体验）？
- [ ] 是否会产生不希望的玩家行为？
- [ ] PVP 游戏：是否对公平性有影响？

### 商业层（如涉及付费）
- [ ] 是否明确区分了外观付费 vs 战力付费？
- [ ] 随机性是否透明（概率公示 + 保底）？
- [ ] 是否制造了不必要的焦虑感？

---

## 🟡 核心循环评审清单

- [ ] 能描述核心循环的"行动→反馈"链吗？
- [ ] 循环的平均时长是多少？是否符合目标受众的会话习惯？
- [ ] 连续重复10次，第10次是否仍然有趣？
- [ ] 循环内是否有足够的玩家决策点（而非纯自动）？
- [ ] 玩家失败时，再来一次的欲望是否足够强？

---

## 🟠 叙事设计评审清单

- [ ] 玩法与叙事是否一致（无 Ludonarrative Dissonance）？
- [ ] 关键角色是否有多层次（表层/中层/深层）？
- [ ] 每段对话是否都在推进剧情/揭示角色/建立关系？
- [ ] 节奏是否有张有弛（高潮后有舒缓）？
- [ ] 环境叙事是否存在（场景本身在讲故事）？

---

## 🔴 数值平衡评审清单

- [ ] 最强构建 vs 最弱构建的差距是否在可接受范围？
- [ ] 经济产出/消耗比是否平衡（货币不会快速积压或枯竭）？
- [ ] 随机奖励是否有保底机制？
- [ ] 新手期成长速度是否足够快（让玩家建立信心）？
- [ ] 后期是否还有有意义的成长目标？

---

## 🟢 关卡设计评审清单

- [ ] 玩家不看地图/攻略也能找到正确方向吗？
- [ ] 每个关卡是否引入了新的设计概念（或新的使用方式）？
- [ ] 关卡是否有环境叙事（场景有记忆点）？
- [ ] 难度是否在心流通道内（不太难也不太简单）？
- [ ] 关卡序列整体节奏是否有张弛（Boss后有缓冲）？

---

## ⚫ 发布前最终检查

- [ ] 新手前30分钟有没有致命的流失点？
- [ ] 核心系统有没有没被覆盖的边缘 Bug？
- [ ] 付费设计是否合规（概率公示、未成年保护）？
- [ ] 社区运营计划是否与游戏内社交设计配合？
- [ ] 是否有明确的发布后迭代计划（热修复 + 版本更新）？

---

*清单不能替代真实玩家测试。这是最后一道"理性检查"，但玩家感受永远是最终裁判。*
