# 数值设计 / 经济系统 / 平衡方法论

---

## 1. 数值设计的本质

### 数值是时间的编码

一切游戏数值，本质上都是**玩家时间的表示**。

```
1000金币 = X分钟的游戏时间
+10攻击力 = 缩短Y%的战斗时长
传说装备 = 投入了Z小时的证明
角色等级 = 走过的游戏旅程长度
```

当你给玩家一件道具，给的不只是属性，而是**对他们时间的认可**。

### 数值设计的三层目标

1. **体验层**：数字的变化要让玩家"感受到"成长
2. **平衡层**：数字要让游戏保持公平或预期的不平衡
3. **经济层**：数字的产出/消耗要让玩家保持参与动力

## 2. 属性设计

### 属性体系的两大派系

**加法体系**（大多数手游）：
```
总攻击 = 基础攻击 + 武器攻击 + 技能加成 + buff加成
优点：计算直观，易于理解
缺点：数值膨胀严重，后期需要通货膨胀处理
```

**乘法体系**（复杂RPG）：
```
总攻击 = 基础攻击 × (1 + 武器加成%) × (1 + 技能加成%)
优点：各来源权重平衡，不易单点极端
缺点：计算复杂，需要专门的数值工具
```

### 数值可感知性设计

**玩家感知的对数律（Weber-Fechner Law）**：感知变化与刺激强度成对数关系。

实际含义：
- 从1攻击→100攻击：玩家感觉巨大变化
- 从1000攻击→1100攻击：玩家几乎感觉不到（同样+100）

**设计应对**：
1. 成长曲线要指数式设计，让玩家持续感知到增幅
2. 后期数值升级要比早期更大的绝对值，才能保持同等感知
3. 或者切换单位（换算成"倍"而非"点"）

## 3. 经济系统设计

### 货币体系架构

**单货币体系**：简单直接，但难以分离不同体验

**多货币体系**（手游常见）：

| 货币类型 | 获取方式 | 消耗用途 | 设计目的 |
|---------|---------|---------|---------|
| 硬货币（钻石/元宝）| 充值/珍贵奖励 | 高价值内容 | 付费转化 |
| 软货币（金币）| 日常游戏 | 基础消耗 | 参与感 |
| 活动货币 | 特定活动 | 活动商店 | 留存驱动 |
| 声望/贡献 | 社交行为 | 社交系统 | 社交粘性 |

**多货币体系风险**：过多货币类型让玩家困惑，要限制在4种以内且用途清晰。

### 经济平衡：产出 vs 消耗

```
健康经济：
  产出速率 ≈ 消耗点总吸引力
  玩家有东西可追求（存在供不应求的高价值物品）
  但基础体验不被付费锁住

通货膨胀（产出 > 消耗）：
  货币泛滥 → 货币贬值 → 玩家失去积累动力
  症状：高端物品价格飞涨，普通玩家放弃追求

通货紧缩（消耗 > 产出）：
  资源稀缺 → 玩家感到被剥夺 → 付费压力过强
  症状：玩家明确感到"不氪不能玩"
```

### 经济系统的四个水龙头

```
生产 Faucets                消耗 Sinks
（货币进入系统）              （货币离开系统）
  ↓                           ↑
怪物掉落           ─→  ─→     装备强化
任务奖励           ─→  ─→     商店购买
活动奖励           ─→  ─→     技能升级
付费充值           ─→  ─→     交易手续费
```

设计核心：始终监控生产/消耗比，确保系统不会过快积累或耗尽。

## 4. 战斗数值平衡

### DPS 框架

基础战斗数值围绕 DPS（每秒伤害）展开：

```
DPS = 攻击力 × 命中率 × 暴击倍率 × 攻击速度
     ÷ （1 - 格挡率）
     ÷ 防御减免系数
```

**设计路径**：先确定每个难度阶段玩家的预期 DPS，再反推怪物HP应该是多少（让玩家在目标时长内击杀）。

### 战斗平衡的几何关系

**克制关系（石头剪刀布）**：
```
A 克制 B → B 克制 C → C 克制 A
（不存在绝对最优解）
```

单纯的数值差异无聊；克制关系创造策略深度。好的克制系统让玩家在战前就开始思考。

### 职业/英雄平衡原则

每个角色应该：
1. 有一个**最擅长**的场景（存在价值）
2. 有一个**明显弱点**（不能全能）
3. 任何时候都有至少一个有竞争力的**使用场景**

OP（过强）的危害：玩法同质化，其他角色失去意义
UP（过弱）的危害：玩家感到时间浪费，流失玩家

## 5. 难度曲线数值化

### 难度设计的数值工具

**RPG难度曲线（预期玩家等级 vs 关卡推荐等级）**：

```
推荐等级
  ↑       玩家实际等级（如果速度合理）
  │  ╱ ← 过快→玩家超等，游戏太简单
  │ ╱╲
  │╱  ╲ ← 关卡推荐等级的波动（Boss关上升）
  └──────────────→ 游戏进度
```

关键数值参数：
- 玩家每小时期望经验量
- 关卡怪物的等级区间
- Boss挑战的等级缓冲区（玩家应略低于或等于推荐等级时有挑战感）

### 成长速度的哲学

**快速成长**（休闲/手游倾向）：
- 优点：新玩家快速感受到成就感
- 缺点：成长期短，很快进入无聊的"维护期"

**慢速成长**（硬核/主机倾向）：
- 优点：每一点成长都有重量感
- 缺点：新手期长，门槛高，流失风险大

**分段成长**（最优解）：
- 早期快速（帮新手过门槛）
- 中期稳定（维持参与节奏）
- 后期极慢（让肝帝感受目标的重量）

## 6. 随机性与确定性的平衡

### 随机性的类型

| 类型 | 时机 | 影响 | 玩家感受 |
|------|------|------|---------|
| **输入随机性** | 玩家做决策前 | 影响决策变量 | 有趣（扑克牌摸牌）|
| **输出随机性** | 玩家做决策后 | 影响执行结果 | 沮丧（射击不命中）|
| **涌现随机性** | 系统运行时 | 产生意外场景 | 惊喜（Rogue元素）|

**设计原则**：输入随机性制造有趣的决策；输出随机性（纯粹的运气好坏）要谨慎使用，因为它让玩家感觉无法控制。

### 保底（Pity）机制设计

对于重要随机奖励，保底机制是玩家信任的基石：

```
标准保底：
  前N次未获得目标时，第N+1次保证获得
  
软保底：
  随着连续未中，概率逐渐提升（不是突然100%）
  更平滑，极端运气情况减少

记忆保底：
  账号级别保底，不因更换卡池重置
  最受玩家尊重的形式
```

一旦承诺了保底机制，**绝对不能缩水**——这是游戏经济设计中最重要的信任合同之一。
