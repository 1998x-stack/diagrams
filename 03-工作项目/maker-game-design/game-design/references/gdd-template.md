# 游戏设计文档（GDD）标准模板与撰写指南

> GDD 不是小说，也不是学术论文。它是一份让团队成员理解游戏愿景并协同执行的工作文档。
> 好的 GDD 是活的——随着项目推进不断更新，而不是一次写完束之高阁。

---

## GDD 标准结构

### 一、游戏概览（Executive Summary）
*长度：1页以内，能让决策者在5分钟内理解这个游戏*

```
游戏名称：[正式名 / 代号]
开发平台：[iOS / Android / PC / 主机]
目标受众：[年龄 / 玩家类型 / 关键特征]
游戏类型：[主类型] + [副类型]
核心体验（1句话）：[玩家将体验到什么？]
核心差异化（1-2句）：[为什么这款游戏与众不同？]
预计开发周期：[阶段划分]
商业模式：[买断 / 免费+内购 / 订阅]
```

**一句话描述模板**：
> "[目标受众] 可以通过 [核心动词] 来 [核心体验]，这在市场上是独特的，因为 [差异化]。"

---

### 二、核心体验定义

**2.1 情绪目标**
- 玩家在游戏过程中应该感受到什么？（用具体情绪词汇，如：紧张、自豪、治愈、热血）
- 游戏结束时，玩家应该有什么感受？

**2.2 核心体验柱（3-5个）**
每个体验柱是游戏设计的顶层约束，所有功能决策都应服务于它。

```
体验柱示例（治愈农场游戏）：
  ① 治愈与放松：所有机制要让玩家感到舒缓，没有压迫感
  ② 创造归属：玩家的农场是独一无二的，是自我表达的空间
  ③ 小成就的积累：频繁的小满足感，每次游玩都有收获
```

**2.3 设计原则（Do & Don't）**
```
DO:
  ✅ 允许玩家以自己的节奏游玩
  ✅ 所有挑战都有多种解法
  ✅ 失败要有意义（学到东西）

DON'T:
  ❌ 强制社交或制造焦虑
  ❌ 有一个绝对最优解的策略
  ❌ 死亡/失败无惩罚（会让挑战无意义）
```

### 三、核心循环设计

**3.1 核心循环（秒/分钟级别）**
```
行动1 → 行动2 → 行动3 → 奖励 → 回到行动1
每次循环时长：[X分钟]
核心乐趣来源：[为什么重复这个行为是有趣的？]
```

**3.2 中观循环（天/周级别）**
- 每日登录触发什么？
- 每周有哪些内容更新？
- 中观循环如何与核心循环连接？

**3.3 宏观循环（月/赛季级别）**
- 长期目标是什么？
- 赛季/资料片如何组织？
- 如何维持老玩家的长期参与？

---

### 四、玩家旅程（Player Journey）

**新手期（0-30分钟）**
- 教学目标：玩家需要学会什么？
- 情绪目标：第一次登录应感受到什么？
- 钩子设计：什么让玩家想继续玩？

**成长期（1-30小时）**
- 系统解锁顺序
- 主要成就里程碑
- 社交引入时机

**核心期（30小时以上）**
- 核心玩家的日常循环是什么？
- 深度内容是什么？
- 社区玩法如何驱动留存？

**流失防护**
- 关键流失节点是哪里？
- 每个节点的干预手段是什么？

---

### 五、游戏系统设计

**5.1 [系统名称] 设计文档模板**

```
系统名称：
系统目标：[这个系统为玩家提供什么体验？]
核心机制：[规则是什么？]

玩家流程：
  1. [步骤1]
  2. [步骤2]
  3. [步骤3]

输入：[玩家做什么触发这个系统？]
输出：[系统给玩家什么反馈/奖励？]

参数设计：
  [参数名] = [值/公式] （说明：[为什么是这个值？]）

边界条件：
  [异常情况1] → [处理方式]
  [异常情况2] → [处理方式]

风险：
  [可能的问题] → [预防/缓解方案]

评审标准（怎么判断这个系统做成功了）：
  □ 玩家无需教学能理解基础规则
  □ 核心乐趣无需外部奖励驱动
  □ 系统参数在合理范围内平衡
```

### 六、世界观与叙事

**6.1 世界观概述**
- 世界背景（一段话）
- 世界运行的核心规则（2-5条）
- 世界的核心矛盾/张力

**6.2 主叙事线**
- 主角是谁？从哪里来？
- 核心冲突是什么？
- 叙事弧线（开端 → 发展 → 高潮 → 结局）
- 玩家选择如何影响叙事？

**6.3 关键角色档案**

```
角色名：
类型：[玩家角色 / 盟友 / 反派 / NPC]
外表描述：
性格特征：[3个形容词]
核心动机：[他/她真正想要的是什么？]
隐藏的创伤/矛盾：[使角色立体的深层内容]
与玩家的关系：
标志性台词/口头禅：
```

---

### 七、数值设计

**7.1 核心数值框架**
- 基础属性列表及定义
- 成长公式
- 关键数值范围（最小值/最大值/典型值）

**7.2 经济设计**
- 货币类型及用途
- 主要产出来源及速率
- 主要消耗点及预期消耗量
- 经济平衡目标

**7.3 难度曲线**
- 阶段划分
- 每个阶段的推荐玩家强度
- 关键难度节点（Boss、新手引导、精英区）

---

### 八、商业化设计

**8.1 商业模式**
- 主要付费方式
- 免费玩家的完整体验描述（保证他们不被歧视）
- 付费玩家获得的额外内容

**8.2 付费点设计**
```
付费点名称：
内容描述：
价格区间：
目标用户：[谁会为此付费？]
情感触发点：[玩家在什么心理状态下最可能付费？]
是否影响公平性：[是/否] （是的话需要特别审查）
```

**8.3 留存与变现关系**
- 哪些留存设计会促进付费意愿？
- 哪些变现设计有损留存（需要权衡）？

---

### 九、技术可行性备注

**9.1 核心技术需求**
- 关键技术特性（物理系统、AI、生成等）
- 已知技术风险

**9.2 平台限制与考量**
- 性能预算（多边形/材质/内存）
- 平台特殊规则（如苹果的随机概率公示要求）

---

### 十、迭代计划与里程碑

```
Milestone 0 - 核心体验原型（[日期]）
  目标：验证核心循环是否有趣
  交付物：可玩的粗糙原型

Milestone 1 - 竖版演示（[日期]）
  目标：完整一段游戏体验
  交付物：可用于用户测试的 Demo

Milestone 2 - Alpha（[日期]）
  目标：所有主要系统可运行
  交付物：内部测试版本

Milestone 3 - Beta（[日期]）
  目标：内容完整，修复已知 Bug
  交付物：外部测试版本

Release（[日期]）
```

## GDD 写作指南

### 好 GDD 的特征

1. **读者导向**：每个章节都清楚知道谁在读、读了要做什么
2. **结论先行**：重要判断放在段落开头，细节在后
3. **可执行**：设计意图明确，实现者知道怎么做
4. **有原因**：不只说"是什么"，还说"为什么"
5. **承认不确定性**：标注哪些是确定的，哪些是待验证的

### 常见错误

- **空谈体验不给机制**："玩家应该感到有趣" → 怎么让他们感到有趣？
- **没有数值只有描述**："成长感很强" → 强化到多少？多快？
- **不区分 MVP 和愿景**：把未来3年都想做的东西全写进第一版
- **没有边界条件**：只写正常情况，不写边缘和异常

### 版本管理建议

```
GDD-v0.1-概念稿.md  → 团队立项讨论用
GDD-v0.5-原型稿.md  → 原型开发参考
GDD-v1.0-Alpha稿.md → Alpha阶段基准
GDD-CURRENT.md      → 永远指向最新版本
```

变更记录要保留在文档底部，重大变更要注明原因。
